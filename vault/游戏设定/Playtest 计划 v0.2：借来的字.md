# Playtest 计划 v0.2：借来的字

> 测试对象：[[纸上原型 v0.2：借来的字]] 的规则 1（捡字）和规则 2（拼句）。
> 背景：[[blog-Exploration7-Gameplay|Exploration 7]]。
> 这次测试和 Web Tools 课的期末项目一起进行：测试用的网页工具就是期末作业，见「5. 测试工具」。

---

## 1. 概要

| 项目 | 内容 |
|---|---|
| 测试类型 | 核心机制原型测试（形成性测试）：只测一个循环，不测完整游戏 |
| 测什么 | 捡字 → 拼句 → 翻面看来源 → 第二天读昨晚的句子 |
| 不测什么 | 故事、「指向」解锁、红圈、归零、角色代入（见第 10 节） |
| 参与者 | 3 人（最少 2 人） |
| 时长 | 每人连续 4 天，每天约 10–15 分钟，外加第 1 天的观察和最后的访谈 |
| 主问题 | **只能用别人给的字描述自己，而且不知道字是谁给的，玩家会不会开始在意这些字的来源？** |
| 产出 | 测试报告，并据此改出纸上原型 v0.3 |

---

## 2. 体验目标与假设

**体验目标（一句话）**
> 玩家在拼句时意识到，自己只能用别人给的字来描述自己，并开始在意这些字是从哪里来的。

**假设**
- **H1（核心）**：来源隐藏时，拼完再翻面看到来源，会让玩家产生明显的情绪反应（惊讶、不舒服、想改句子），并让他们之后捡字时更在意来源。
- **H2**：最多 6 张字条的限制会逼出取舍。玩家会犹豫、换字，而不是随手拼完。
- **H3**：「给明天的自己写一句话」会产生跨天的连续感：第二天读到昨晚的句子，会影响当天捡什么字。

---

## 3. 研究问题

主问题是 Q4，其他是附带观察。

| # | 问题 | 观察指标 | 结果会影响的设计 |
|---|---|---|---|
| Q1 | 规则好懂吗？不解释能上手吗？ | 第一次拼句前提问的次数；卡住的步骤 | 新手引导 |
| Q2 | 限制的强度对不对？ | 拼句用时；句子能否读懂（第三方判断）；放弃或乱拼的次数；每天口袋字数和实际用字数 | 字条上限；每天给多少字；给单字还是词组 |
| Q3 | 拼句是不是一个真正的选择？ | 换字次数；犹豫时长；边想边说时有没有出现「想要 A 但只能留 B」 | 「每晚只能拼一句」能不能撑起每天的高潮 |
| **Q4** | **来源有没有作用？** | 翻面时的即时反应（观察记录）；翻面后想改句子的比例；之后是否主动问「这个字是谁的」；捡字时的来源分布是否变化 | 来源机制和红圈要不要加强、怎么呈现 |
| Q5 | 跨天有没有连续感？ | 第 2 天以后，当天捡的字和昨晚的句子在词义上是否有关联；访谈中的自述 | 「本子」这个仪式要不要加强 |

## 4. 测试设计

### 4.1 两种字池

| 天数 | 字池 | 目的 |
|---|---|---|
| 第 1 天（有人在旁观察） | **游戏字池**：v0.2 第 1 天的字条（见附录 A），来源事先标好 | 测规则本身（Q1–Q3），测试者扮演角色，感受会弱一些，但条件统一 |
| 第 2–4 天（自己在家完成） | **生活字池**：测试者自己当天拍下或复制的文字（路牌、广告、家人的消息、自己的旧笔记、书） | 测「借字认识自己」本身有没有力量（Q4、Q5）。情感最真实 |

先用游戏字池，可以让测试者在没有个人压力的情况下学会规则。之后改用生活字池。

### 4.2 来源条件

- **主条件（P1、P2）**：捡字时自己给每张字条标上来源（我自己 / 家人 / 世界）。**拼句时看不到来源**，拼完后必须「翻面」才能看到。
- **对照条件（P3，人数够时）**：拼句时来源一直可见。
- 只改这一个变量，其他全部固定：每句最多 6 张，每天拼 1 句，测 4 天，说明文字相同。

> 注：生活字池里的来源由测试者自己标，所以「隐藏」其实是「拼的时候先不显示」。测的不是「猜不猜得到」，而是「拼完以后再面对来源」这一刻。

### 4.3 每天的流程

1. **早上**：打开工具，先看到昨晚的句子（第 1 天没有这一步）。
2. **白天**：捡字。生活字池每天最少 10 张、最多 20 张字条。
3. **晚上**：从当天口袋里选最多 6 张，拼一句「关于自己」的话。
4. **翻面**：看每张字条的来源，可以写一句感想（选填）。
5. 工具自动保存当天记录。

### 4.4 时间表（暂定）

| 时间 | 事项 |
|---|---|
| 11-16 – 11-22 | 写完本计划；做工具最小版本；找参与者 |
| 11-23 前后（第 11 周） | 期末提案；工具先在自己身上跑一次（试点） |
| 第 12 周 | 根据试点修工具；P1–P3 第 1 天观察场次 |

| 第 13–14 周 | 分析，写测试报告，改出 v0.3；整理作业文档 |

## 5. 测试工具（Web Tools 期末项目）

工具的内容是通用的，不和 thesis 绑定。它是一个「拼字类机制」的测试工具：设计者设定字池、规则和来源标签，测试者在里面捡字、拼句，工具自动记录过程。这次只是把 v0.2 的规则装进去。

**这次测试需要的功能**
- [ ] 载入预设字池（附录 A，JSON）
- [ ] 捡字：上传或拍照 → OCR → 点选词语，裁成字条；粘贴文字也可以
- [ ] 给字条标来源（标签可以自定义，这次是：我自己 / 家人 / 世界）
- [ ] 规则设置：每句最多几张、每天拼几句、拼句时来源是否隐藏
- [ ] 拼句画布：拖拽排序，字条保留原图质感
- [ ] 翻面，并可写一句感想
- [ ] 早上先显示昨晚的句子
- [ ] 自动记录（字段见第 7 节），可导出 JSON 和图片
- [ ] 数据只存在测试者自己的浏览器里，最后由测试者导出发给我

**试点时要检查**：中文 OCR 切词是否够准（不够就让测试者自己框选）；手机上能不能顺手地拍照捡字。

## 6. 参与者

**人数**：3 人（最少 2 人），另加我自己做一次试点（不计入结果）。

**招募标准**
- 必需：愿意连续 4 天每天花 10–15 分钟；有手机，方便拍照捡字。
- 优先：有写日记、写诗、拼贴或做游戏的习惯；至少 1 人来自东亚家庭（「别人期待的词」会更明显）；至少 1 人没听我讲过这个游戏。
- 避免：深度参与过 v0.1、v0.2 讨论的人（他们已经知道设计意图）。

**知情同意（开始前口头说明，并写在工具首页）**
- 生活字池可能涉及家人的消息和私人文字：**只捡你愿意给我看的**，拍到他人姓名或敏感内容的部分可以不选。
- 报告和博客中参与者匿名为 P1 / P2 / P3，句子引用前先征得同意。
- 作业要求公开姓名和照片：单独征求同意，不同意的人可以只出现在 thesis 报告里。
- 可以随时退出，已有的数据会删除。

## 7. 数据收集

### 7.1 工具自动记录

每个事件记一条：`{参与者, 天数, 时间戳, 事件, 对象, 附加}`

| 事件 | 附加信息 |
|---|---|
| `pick`（捡字） | 字条文字、来源、取自什么材料 |
| `place` / `remove` / `reorder`（拼句操作） | 字条 id、位置 |
| `submit`（完成句子） | 最终句子、用时、字条数、来源比例 |
| `flip`（翻面） | 翻面后到下一步的停留时长 |
| `revise_wish`（翻面后想改） | 是 / 否 |
| `note`（感想） | 文字 |
| `morning_view`（早上看昨晚的句子） | 停留时长 |

### 7.2 观察记录（第 1 天场次）

请测试者**边做边说**（think-aloud）。只在对方卡住超过 1 分钟时才给提示，并记下这次提示。

| 时间 | 步骤 | 测试者说了 / 做了什么 | 情绪（中性 / 犹豫 / 兴奋 / 不适） | 我的提示（如有） |
|---|---|---|---|---|
|  |  |  |  |  |

### 7.3 每日一句（工具内，选填）

翻面后：「看到来源，你想到了什么？」

### 7.4 测后访谈提纲（约 20 分钟，录音需同意）

1. 用一句话说说这 4 天是在做什么。
2. 哪一刻最有感觉？哪一刻最无聊？
3. 拼句的时候你在挑什么样的字？有没有想说却拼不出来的话？
4. 翻面看到来源时你在想什么？哪一次最意外？
5. 你会想改掉某句话吗？为什么？
6. 早上看到昨晚的句子时，是什么感觉？会影响你那天捡什么吗？
7. 6 张字条够吗？要多还是要少？
8. （P3）一直看得到来源，会影响你选字吗？
9. 如果这是一个游戏的一部分，你想知道接下来会发生什么吗？

## 8. 分析方法

- **定量（描述统计即可，样本太小，不做显著性）**：每天拼句用时、换字次数、来源比例、翻面后想改句子的比例，按天画出变化。
- **定性**：把观察记录、每日一句和访谈转写成便利贴，做亲和图分组。重点找：
  - 对来源的反应；
  - 对限制的抱怨或赞赏；
  - 跨天的联系。
- **句子本身**：把所有句子按参与者、天数排好，看能不能读懂、有没有变化。另请 1 位没参与的人盲读，评「是否读得懂」「是否像在说一个人」。
- 每个假设最后给出：**成立 / 部分成立 / 不成立**，附证据。

## 9. 决策标准（提前写好，避免事后解释）

| 如果看到…… | 那么 v0.3 就…… |
|---|---|
| 多数人翻面时没什么反应（H1 不成立） | 来源本身不够有力。需要靠剧情（红圈、妈妈的钥匙）或更强的呈现（字迹、颜色）来承载 |
| P3（来源可见）和 P1、P2 的选字差不多 | 「隐藏」不是关键，关键可能是「谁给的」本身。可以考虑简化成来源可见 |
| 多数人拼不出读得懂的句子 | 字太碎或太少：改给词组，或者每天多给几张 |
| 多数人很快拼完、几乎不换字（H2 不成立） | 限制没有逼出取舍：减到 4 张，或者让字条之间互相冲突 |
| 多数人早上不看或者跳过昨晚的句子（H3 不成立） | 「给明天写」的仪式要加强，或者把它做成剧情的强制节点 |
| 有人说「像在被审问」或感到不适 | 记下来，这可能正是想要的感受，也可能太重。和指导老师讨论 |

## 10. 范围外与已知偏差

**这次测不到的**
- 故事吸引力。
- 「指向」解锁新物件或地点。
- 红圈（两个来源无法分辨）。
- 归零。
- 内心声音的变化。
- 角色代入感。

这些留给之后的游戏原型。

**已知偏差**
- **生活字 ≠ 游戏字**：测试者写的是自己，游戏里玩家写的是「她」。生活字池测出的是机制在真实情感里的力量，不等于角色代入后的体验。
- **自己标来源**：生活字池里的来源是测试者自己标的，比游戏里「完全不知道」弱。
- **样本小，熟人偏多**：熟人可能会说好话。访谈时问具体的事件，不问「好不好」。
- **工具本身的可用性**：OCR 或拖拽不好用会干扰结果。记录里要区分「规则的问题」和「工具的问题」。
