> [!note] Update 1 笔记（从 Notion 导入）
> Link:
> [https://www.inkandswitch.com/essay/malleable-software/](https://www.inkandswitch.com/essay/malleable-software/)
> Type:
> Design essay / research concept / software philosophy
> Focus:
> How software could give users more control to adapt, modify, and reshape their digital tools.
> Main idea:
> Most modern software is designed as a finished product. Users can change a few settings, but they usually cannot meaningfully change how the software works.Malleable software proposes that users should be able to adapt software to their own needs with minimal effort.
> Software should not force users to adapt themselves to the tool. The tool should be able to adapt to the users.
> Different users have different needs, workflows, abilities, and preferences. A mass-produced application cannot anticipate every possible need.
> Why it is interesting:
> This is highly relevant to accessibility. Disabled users often have very specific and individual needs, but many products provide only general settings designed by the company.
> A more adaptable system could allow users to adjust:
> - Layout
> - Navigation
> - Text size
> - Information density
> - Input methods
> - Feedback types
> - Timing
> - Labels
> - Workflow
> - Output format
> Potential connection to my thesis:
> This gives me a way to think about accessibility beyond fixed features. Instead of designing one product for one “average” disabled user, I could explore how a digital tool allows users to make small adjustments according to their individual needs.
> Possible connection to AI:
> AI could help users customise software through natural language. For example, a user could say:
> - “Make this interface less crowded.”
> - “Show me only the most important information.”
> - “Give me more time to complete this task.”
> - “Read this in simpler language.”
> - “Use larger buttons.”
> - “Turn these instructions into a checklist.”
> However, AI should not make these decisions secretly. Users should be able to review, change, and undo the adaptations.
> Questions:
> - How much control do users need over their digital tools?
> - Which customisations are most valuable for disabled users?
> - Should customisation be manual, automatic, or AI-assisted?
> - Can users understand what the system has changed?
> - How can a system remain simple while still being flexible?
> - Can different users share adaptations with each other?
> - How can users undo or correct an adaptation?
> - Is a highly flexible product always better?
> - Could too many choices create cognitive overload?
> Personal reflection:
> This essay helps me think about accessibility as adaptability. A product may not need to predict every user’s needs in advance if it allows users to reshape the product themselves.
