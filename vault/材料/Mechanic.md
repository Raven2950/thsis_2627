> [!note] Update 1 笔记（从 Notion 导入）
> Link:[https://mechanic.design/](https://mechanic.design/)
> Type:
> Open-source framework / web-based design tool / creative coding tool
> Focus:
> Creating custom web-based design tools that generate design assets directly in the browser.
> Main idea:
> Mechanic allows designers to turn their own design rules and decisions into reusable tools. Instead of manually producing every asset, the designer writes a function that generates images, videos, or other design outputs.
> What it does:
> - Turns design rules into functions
> - Generates assets in the browser
> - Creates custom project-specific design tools
> - Allows outputs such as SVG, PNG, and WEBM
> - Automates repetitive design work
> - Uses familiar web technologies
> - Provides a browser-based canvas for previewing designs
> Why it is interesting:
> Mechanic is not simply a design software like Figma or Photoshop. It allows designers to create a smaller, more personalised tool for a specific design problem.
> The interesting shift is:
> Instead of adapting my workflow to an existing software tool, I can create a tool that matches my workflow.
> What problem does it address:
> Many design tools are general-purpose and require designers to repeat similar processes manually. Mechanic allows designers to encode their decisions and automate repetitive production.
> Important design concept:
> Designers can become toolmakers.
> Potential connection to my thesis:
> This is relevant to my interest in software-based products and web tools. It suggests that a product does not always need to be a large platform or a complete application. It can be a small, focused tool designed around a specific user need or workflow.
> It may also be relevant to accessibility because different users may need different ways to work with software. Instead of forcing every user to use the same interface, a tool could allow users or communities to create customised workflows.
> Questions:
> - Could a future accessibility tool be customised by the users themselves?
> - Could users create their own interface, workflow, or output format?
> - How much customisation is useful before a tool becomes too complicated?
> - Can a tool adapt to different abilities without requiring users to code?
> - Could AI help users customise a tool using natural language?
> - What is the difference between personalisation and user-created tools?
> Limitations:
> Mechanic is mainly focused on designers and generated visual assets. It may require coding knowledge, so it is not immediately accessible to all users.
> This creates an interesting design question:
> How can a customisable tool be made accessible to people who are not programmers?
> Possible research direction:
> Designing a software tool that allows users to adapt a digital experience to their own needs without needing to write code.
> Personal reflection:
> Mechanic made me think about software not only as something I use, but also as something I can design and reshape according to a specific user group or workflow.
